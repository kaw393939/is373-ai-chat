## Executed verification

- **58 unit/integration tests passed against PostgreSQL 17**, Python 3.14.7,
  macOS arm64. A new capped PostgreSQL container held only synthetic test data;
  loopback SSH forwarding reached its dedicated database. The container and
  forwarding were removed after the run. No application database was migrated
  or reset. Measured Python `app` coverage: 795 statements and 166 branches,
  none missing; **100% under the existing documented exclusions**. Frontend and
  operational scripts are outside that metric.
- Default temporary-SQLite run: **56 passed, 2 skipped**. Skips concern PostgreSQL
  locks; this run reaches 99.79% and does not satisfy the 100% coverage gate. It is
  a quick path, not a replacement for the PostgreSQL run.
- **Three Python Playwright journeys passed** using `scripts/run-browser-lab.py`:
  registration/approval/private chat/history/rename/retry/delete; mobile history
  and password reauthentication; administration/budgets/mock-stream stop/logout.
  The server and SQLite database were removed by the harness.
- Twelve new guard cases cover database reset refusal, query-host overrides,
  public/proxy-like browser URL refusal before networking, absence of migrations
  and app construction on fixture refusal, and nonce/mock-identity rejection.
- Git history credential-pattern scan: **202 historical blobs**, **8 Actions
  runs / 36 log files**, no matching provider/GitHub token or private-key-header
  candidates. Tracked configuration examples contain placeholders; private
  `.state`, real `.env`, SSH keys and account screenshots are excluded. Pattern
  checks are limited detection evidence, not proof that every possible secret
  format is absent. Public access follows the owner's explicit decision.

Container/image-specific lab evidence and rendered-HTML checks are recorded in
the book workflow for the exact source SHA. Each lab distinguishes authored

No live provider request, outbound mail, public admin mutation or production
